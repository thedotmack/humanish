# Plan: humanish — build the single-user MVP

**One-line:** Lift claude-magic's link broker, generalize the credential below it from "one BrightData token" to "many named browser-cookie profiles," and bolt a Playwright login jail to its front. Ship NotebookLM slide-deck generation as the first action.

**Outcome the MVP must hit:** Operator opens the humanish dashboard, logs into Google inside an embedded neko Chromium tab, names the profile `google-personal`, mints a two-word EFF slug, pastes the served skill markdown into a fresh claude.ai web chat, asks "turn this paper into a kawaii deck," and within ~10 minutes receives a `https://wooow.now/<slug>` URL inline in the same conversation. Zero shell. Zero Claude Code. Zero local setup.

**Design doc this plan executes:** `reports/2026-05-14-humanish-server.md`.
**Substrate plan it inherits from:** `~/.superset/worktrees/df8069a7-eb08-4626-9d3d-918d1e12eb9f/sequoia-territory/plans/2026-05-12-claude-magic.md`.
**Reusable code substrate:** `~/Downloads/files/{worker.js, wrangler.toml, mint-skill.sh, README.md}` (the brightdata-proxy Worker — fork it).

## Architectural shape (no surprises)

Two tiers, one per trust boundary:

- **Tier 1 — Link broker (Cloudflare Worker).** Public edge. Mints two-word EFF slugs. Renders single-use HTML pages with skill markdown. Burns slugs on first browser visit. Authenticates dashboard traffic via Resend magic links (copied wholesale from wooow.now). Calls Tier 2 over Fly's private network with a shared bearer.
- **Tier 2 — Humanish box (long-running container, single VM on Fly.io).** Hosts: (a) **neko** (`m1k1o/neko/chromium`) for the browser jail viewport — WebRTC-streamed headful Chromium for human login flows; (b) a Node action-runner service that decrypts `storage_state.json` per profile and runs the requested action against an ephemeral Playwright context; (c) `notebooklm-py` CLI as the first action's executor.

Two-tier, Cloudflare-Worker-plus-stateful-container. Same shape as wooow.now's NotebookLM sidecar. Same shape as humanctl's MVP. Same shape we keep arriving at independently per the design doc.

## Phase 0 — Documentation discovery (DONE — read this section before touching code)

### Allowed APIs / patterns the implementation may use

**Cloudflare Workers + Durable Objects + KV.**
- `env.DO_NAMESPACE.idFromName(slug)` + `env.DO_NAMESPACE.get(id).fetch(...)` — routes one slug to one DO instance, serializing concurrent requests. https://developers.cloudflare.com/durable-objects/.
- Inside the DO: `this.state.storage.get(key)` + `this.state.storage.delete(key)` with **no intervening `await`** — automatically atomic per CF docs ("Any series of write operations with no intervening `await` will automatically be submitted atomically"). https://developers.cloudflare.com/durable-objects/api/storage-api/.
- `env.KV.put(key, value, {expirationTtl: <seconds>})` — for short-lived bearers and magic-link tokens.

**Magic-link auth substrate (verbatim copy from wooow.now).**
- Source files: `workers/api/src/auth.ts:1-198` and `workers/api/src/index.ts:232-301` in this repo.
- Public surface, copy these signatures unchanged:
  - `sendMagicLinkEmail(env, email, magicUrl): Promise<void>` — Resend POST to `https://api.resend.com/emails`.
  - `mintMagicToken(env, email): Promise<string>` — 32-char hex, KV `magic:<token>` with 15-min TTL.
  - `consumeMagicToken(env, token): Promise<string | null>` — single-use; deletes from KV.
  - `createSession(env, email): Promise<string>` — 30-day token, stored as `session:<sha256(token)>`.
  - `readSessionUser(req, env): Promise<UserRecord | null>` — reads cookie, hashes, looks up.
  - `buildSessionCookie(token, domain): string` — HttpOnly/Secure/SameSite=Lax/Max-Age=2592000.
- Cookie name for humanish: **`humanish_session`** (not `wow_session`).
- KV namespace: a fresh one (don't share `MANIFESTS` with wooow.now). Bind as `KV` in humanish's `wrangler.toml`.

**brightdata-proxy fork point.**
- Source: `~/Downloads/files/worker.js:1-163`. Keep `corsHeaders`, `randomToken`, `bearer()`, `json()` helpers.
- Drop `/code` and `/redeem` (the owner-key + redeem split). Replace with slug-bound bearer issuance from `/api/mint`.

**EFF Long wordlist.** 7,776 words, CC-BY 3.0. Source: https://www.eff.org/files/2016/07/18/eff_large_wordlist.txt. Two-word slugs = ~60M combos. Bundle as a TS array at Worker build time (not in KV). Retry on collision in `/mint` (max 3 retries).

**Durable Object SlugBox (atomic single-use).** Pattern from `2026-05-12-claude-magic.md:172-205`. One DO per slug. Single key `"v"`. `POST /claim` does `storage.put("v", payload)` — return 409 if already claimed. `GET /consume` does `const v = await storage.get("v"); if (!v) return 410; await storage.delete("v"); return v` — no intervening await → automatic atomic write per CF docs.

**neko (m1k1o/neko).**
- https://github.com/m1k1o/neko. v3.1.0 (April 2026). ~20.9k stars. Actively maintained.
- Prebuilt image: `ghcr.io/m1k1o/neko/chromium:latest`. Single-user mode default. WebRTC = low input latency.
- Embedding docs: https://neko.m1k1o.net/docs/v3/installation/embed.
- CDP attach (for Playwright to capture `storage_state` from neko's Chromium): bind Chromium's debug port to `localhost` only; Playwright connects via `chromium.connectOverCDP("http://127.0.0.1:9223")`. https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp.
- Fallback if WebRTC breaks: KasmVNC (https://github.com/kasmtech/KasmVNC). Higher input latency but simpler stack.

**Playwright `storageState`.**
- Capture: `await context.storageState({ path?, indexedDB: true })`. https://playwright.dev/docs/api/class-browsercontext#browser-context-storage-state.
- Restore: `await browser.newContext({ storageState })`.
- Shape: `{ cookies: [{name, value, domain, path, expires, httpOnly, secure, sameSite, partitionKey?}], origins: [{origin, localStorage: [{name, value}]}] }`.
- Gotchas:
  - `indexedDB: true` is opt-in (Playwright v1.51+). Required for Firebase Auth and anything that stores JWTs in IndexedDB. Set it.
  - `sessionStorage` is NOT captured by Playwright. NotebookLM doesn't need it.
  - Cookies carry `expires` (unix seconds). Playwright will not refresh — detect 401 and trigger reauth.

**Node WebCrypto AES-GCM** (`globalThis.crypto.subtle`). Stable since Node 15+, zero deps, portable. For each encrypted profile blob: random 12-byte IV, AAD = profile name (binds ciphertext to filename — prevents copy-paste tampering between profiles). Layout: `[12B IV][AES-GCM ciphertext+tag]`. https://nodejs.org/api/webcrypto.html.

**notebooklm-py CLI.**
- PyPI: `notebooklm-py`. Upstream: https://github.com/teng-lin/notebooklm-py.
- Skill on this machine: `/Users/alexnewman/.agents/skills/notebooklm/` (real CLI source at `src/notebooklm/notebooklm_cli.py`).
- Auth model: cookie-jar `~/.notebooklm/profiles/<profile>/storage_state.json` (Playwright shape). Required Google cookies: `SID, HSID, SSID, APISID, SAPISID, __Secure-1PSID, __Secure-3PSID`.
- **Inline auth (use this — no disk write):** `NOTEBOOKLM_AUTH_JSON=<storage_state JSON>` env var. Documented at `SKILL.md:54-58` and `.env.example:8-15`.
- Subcommands needed for the first action:
  - `notebooklm notebook create "<title>" --json` → `{notebook:{id,title}}`.
  - `notebooklm source add <path|url> --json` → `{source:{id,title,type,url}}`.
  - `notebooklm source wait <id>` — blocks until indexed.
  - `notebooklm generate slide-deck -s <source_id> --json` → `{task_id, status}`.
  - `notebooklm artifact wait <task_id>` — blocks until rendered (~8 min per past benchmark, observation 1610).
  - `notebooklm download slide-deck <out.pdf> -a <task_id> --format pdf`.
- Only `notebooklm login` needs Playwright Chromium headful — that runs inside the neko browser jail, not the action runner.
- **Cookie keepalive.** NotebookLM uses `__Secure-1PSIDTS` with ~10-min TTL, auto-refreshed via `accounts.google.com/RotateCookies` on each API call. Reference: `docs/auth-keepalive.md:33-46` in the skill. Action runner runs `notebooklm list` per profile every ~5 min to keep cookies live during idle.

**wooow.now publish API** (the downstream consumer for the first action).
- `POST https://api.wooow.now/api/decks` (multipart): `file` (PDF ≤25MB), optional `title`.
- Auth tier humanish uses: `Authorization: Bearer <UPLOAD_TOKEN>` — admin tier, no quota.
- Response 201: `{id: "<slug>", quota: {...}}`. Share URL: `https://wooow.now/<id>`.
- Server-side impl: `workers/api/src/index.ts:561` in this repo (humanish calls the public endpoint, not the source).

**MacGyver advisor/executor pattern + two-input sanity test.** Copy verbatim from `~/.superset/worktrees/df8069a7-eb08-4626-9d3d-918d1e12eb9f/sequoia-territory/reports/claude-magic-skill-draft.md:70-155`. This is the load-bearing UX of the served skill markdown — do not paraphrase.

### Anti-patterns to avoid

- **Do NOT** have Claude `WebFetch` the slug URL. Claude Code routes non-allowlisted fetches through a Haiku pre-summarizer with explicit anti-instruction prompting. Pre-summarized instructions never reach the main model. The user must visit the slug URL in their own browser tab and paste the markdown into the chat themselves.
- **Do NOT** put long-lived secrets in served skill markdown. Use a slug-bound bearer scoped to `(profile, action_id, payload_shape_hash, ttl, max_calls=1)`.
- **Do NOT** use KV alone for slug single-use. KV is eventually consistent and has no atomic CAS. Use a Durable Object.
- **Do NOT** colocate browser sessions across users. Each user gets a dedicated humanish box. (Cloud multi-tenant version is out of scope; MVP is single-user.)
- **Do NOT** support arbitrary upstream services. Hardcoded `ACTION_ALLOWLIST` of one (`notebooklm.generate-deck`) in MVP. Phishing risk is structural.
- **Do NOT** persist decrypted `storage_state.json` to the action runner's disk. Pipe directly through the `NOTEBOOKLM_AUTH_JSON` env var.
- **Do NOT** bind the action-runner HTTP port to `0.0.0.0`. Bind to `[::1]` only; only the broker (over Flycast) talks to it.
- **Do NOT** include `allow-top-navigation` in the dashboard's neko iframe sandbox.

**1.4 Durable Object SlugBox.** One DO per slug. `POST /claim` stores `{markdown, bearer, profile, action_id, payload_shape_hash, ttl_expires_at, max_calls}` under key `"v"` — return 409 if `storage.get("v")` already returned non-null. `GET /consume` atomic get-then-delete (no intervening await) — returns the markdown blob, marks slug dead.

**1.5 Bearer issuance.** In `/api/mint`:
1. Roll a two-word slug from `EFF_LONG`. Retry up to 3 times on DO `/claim` 409.
2. Generate a 16-byte random bearer (32 hex chars) via `randomToken()`.
3. Compute `payload_shape_hash = sha256(JSON.stringify(sortedShape(payload_shape)))` — the JSON-schema-like description of expected fields, not their values.
4. Store `bearer:<token>` in KV with `expirationTtl = ttl_seconds` (default 14400 = 4h), value = `{profile, action_id, payload_shape_hash, max_calls_remaining: 1}`.
5. Render the skill markdown template (Phase 5) with `{{BEARER}}`, `{{ACTION_URL}}`, `{{ISSUED_AT}}`, `{{EXPIRES_AT}}`, `{{PROFILE}}`, `{{ACTION_ID}}`, `{{PAYLOAD_SCHEMA}}`.
6. POST the rendered markdown to the slug's DO `/claim`.
7. Return `{slug, url: "https://humanish.example/" + slug}`. The dashboard puts the URL in the clipboard via `navigator.clipboard.writeText`.

**1.6 Slug redemption.** `GET /<slug>`:
1. Validate slug shape: `^[a-z]+-[a-z]+$` AND both words in `EFF_LONG` (Set lookup).
2. DO `/consume` → markdown or 410.
3. Render `slug.html.template` with `{{MARKDOWN}}` HTML-escaped and inlined into a `<pre><code>` block + Copy button.
4. Set `Cache-Control: no-store`.

**1.7 Action proxy.** `POST /api/actions/:profile/:action_id`:
1. Extract bearer; KV lookup `bearer:<token>` — if missing/expired, 401.
2. Verify `(profile, action_id)` match the bearer's scope; else 403.
3. Hash submitted payload's shape (same `sortedShape(...)` function); verify matches bearer's `payload_shape_hash`; else 400 with `payload_shape_mismatch`.
4. Decrement `max_calls_remaining`. If now 0, `env.KV.delete("bearer:" + token)`.
5. Forward to box: `POST https://humanish-box.internal:7654/run` with `Authorization: Bearer ${env.BOX_SHARED_SECRET}`, body `{profile, action_id, payload, request_id}`. Stream the response back.

## Phase 2 — Humanish box: container image (neko + action runner + notebooklm-py)

### What to implement

**2.1 Host: Fly.io.** Single VM, single user. One Fly volume `humanish_data` mounted at `/data/` (encrypted profile blobs + audit log). `fly.toml`:
- One machine type (`shared-cpu-2x`, 2GB RAM minimum — neko's Chromium is hungry).
- Mount `humanish_data:/data`.
- Internal port 7654 (action runner) — `internal_port`, NOT public. Reached over Flycast (`humanish-box.internal:7654`) from the broker.
- Public port 8080 (neko WebRTC) — public.

**2.2 Dockerfile.** Base: `ghcr.io/m1k1o/neko/chromium:latest`. Layer on:
- `apt-get install -y python3-pip python3-venv` (Python 3.11+).
- `python3 -m pip install --break-system-packages notebooklm-py==<pinned>` (pin to the latest verified version at build time).
- Node 20+ via NodeSource apt repo.
- `COPY packages/box/action-runner /opt/action-runner` → `npm ci --omit=dev`.
- `ENTRYPOINT`: a tiny bash script that starts neko in background (`/usr/bin/neko --config /etc/neko.yaml &`) and execs the action-runner Node service in foreground (`node /opt/action-runner/dist/server.js`).

**2.3 Action runner service** (Node TS, packaged in the same container, listens on `[::1]:7654`):

- `GET /healthz` → 200 `{ok: true, ts: <iso>}`.
- `POST /run` (bearer-auth via `BOX_SHARED_SECRET`):
  - Body: `{profile, action_id, payload, request_id}`.
  - Read `/data/profiles/<profile>.bin`, decrypt with AES-GCM (key from `HUMANISH_MASTER_KEY`, AAD = profile name).
  - Dispatch to action handler by `action_id`. Phase 4 implements `notebooklm.generate-deck`.
  - Stream response back. On success, append audit line to `/data/audit.log` (`<iso>\t<request_id>\t<profile>\t<action_id>\tok\t<bytes>`).
  - On any error: respond with structured JSON (`{error, code}`) — never include payload contents.
- `POST /profiles/:name/start-login` (bearer-auth):
  - Tells neko to navigate its embedded Chromium to a fresh blank tab (`about:blank`).
  - Server-side state: in-memory `pending_login:<name>` flag (does NOT persist across restarts — login flow must complete in one session).
  - Returns `{neko_url: "https://<fly-app>.fly.dev:8080"}`.
- `POST /profiles/:name/save` (bearer-auth):
  - Connect to neko's Chromium via CDP: `chromium.connectOverCDP("http://127.0.0.1:9223")`.
  - Get the existing default `BrowserContext` (the one the user has been driving).
  - Capture: `const state = await context.storageState({ indexedDB: true })`.
  - Encrypt with AES-GCM, AAD = `<name>`. Write to `/data/profiles/<name>.bin.tmp` then atomically `rename` to `<name>.bin`.
  - Navigate neko's Chromium back to `about:blank` (tears down the saved tab's identity).
  - Clear `pending_login:<name>`.
  - Return `{ok: true, profile: name, bytes: <size>}`.
- `GET /profiles` (bearer-auth):
  - List `/data/profiles/*.bin` filenames stripped of extension. Return `{profiles: [...]}`. Don't decrypt.
- `DELETE /profiles/:name` (bearer-auth):
  - Unlink `<name>.bin`. Return `{ok: true}`.

**2.4 neko config (`/etc/neko.yaml`).** Single-user mode. CDP debug port bound to `127.0.0.1:9223`. Disable session recording. Disable file uploads/downloads in/out of the neko container (the user shouldn't be exfiltrating browser data through the jail). One screen size (1280×720 is fine; let neko handle the rest).

**2.5 Encryption.** `HUMANISH_MASTER_KEY` is a Fly secret: 32-byte base64-encoded random. For each profile:
- `iv = crypto.getRandomValues(new Uint8Array(12))`.
- `key = await crypto.subtle.importKey("raw", base64decode(masterKey), {name: "AES-GCM"}, false, ["encrypt", "decrypt"])`.
- `aad = new TextEncoder().encode(profileName)`.
- `ciphertext = await crypto.subtle.encrypt({name: "AES-GCM", iv, additionalData: aad}, key, plaintextJSON)`.
- Blob layout: `[12B IV][ciphertext+tag]`. Approx 30 lines TS total in `crypto.ts`.

**2.6 Deploy.** `fly deploy` from `packages/box/`. Set Fly secrets:
- `HUMANISH_MASTER_KEY` (32B base64).
- `BOX_SHARED_SECRET` (32B hex — same value also set as a Worker secret on the broker side).
- `WOOOW_UPLOAD_TOKEN` (the wooow.now admin `UPLOAD_TOKEN` value).

## Phase 3 — Browser jail wired to the dashboard

### What to implement

**3.1 Dashboard SPA.** Single HTML page at `/dashboard`, served by the Worker. Vanilla JS (no framework), <50KB total. Three sections:

- **Profiles.** List of saved profiles. Each row: name + "Reauth" button + "Delete" button. Reauth = same flow as fresh login but the box restores the existing `storage_state` first.
- **+ Log in to a new service.** Text input for profile name + button. On click:
  1. POST `/api/profiles/<name>/start-login` → response includes `neko_url`.
  2. Render `<iframe sandbox="allow-same-origin allow-scripts allow-forms" src="<neko_url>">` in a dedicated container div.
  3. Overlay a "Save profile" button in the dashboard chrome (above the iframe, NOT inside it). Clicking it POSTs `/api/profiles/<name>/save` and on 200 swaps the iframe for a success message.
- **Mint a link.** Form with: profile dropdown (populated from `GET /api/profiles`), action dropdown (just `notebooklm.generate-deck` in MVP), TTL slider (1h / 4h / 24h, default 4h), "Mint" button. On click POSTs `/api/mint`, copies result URL to clipboard via `navigator.clipboard.writeText`, flashes "Copied. Paste into Claude."

**3.2 Reauth flow.** Same as fresh login but `start-login` accepts `?restore=true` — the box decrypts the existing profile, opens an ephemeral Playwright context with `storageState` restored, navigates to a sentinel URL that proves login worked (e.g., https://notebooklm.google.com for a google-* profile), and only THEN hands control to the neko viewport. User completes the "your session expired" flow if needed, clicks Save, box recaptures.

## Phase 4 — First action: `notebooklm.generate-deck`

### What to implement

**4.1 Action module** at `packages/box/action-runner/src/actions/notebooklm-generate-deck.ts`:

```ts
import { z } from "zod";
import { execFile } from "node:child_process";
import { promisify } from "node:util";
import { promises as fs } from "node:fs";
import path from "node:path";
const exec = promisify(execFile);

export const NOTEBOOKLM_GENERATE_DECK = {
  id: "notebooklm.generate-deck" as const,

  inputSchema: z.object({
    source_text: z.string().min(100, "source must be at least 100 chars"),
    title_hint: z.string().min(1).max(120).optional(),
  }),

  outputSchema: z.object({
    wooow_url: z.string().url(),
    title: z.string(),
    bytes: z.number().int().positive(),
    notebooklm_artifact_id: z.string(),
  }),

  async run({ payload, storageStateJson, env, requestId }) {
    const cliEnv = { ...process.env, NOTEBOOKLM_AUTH_JSON: storageStateJson };
    const tmpDir = `/tmp/humanish-${requestId}`;
    await fs.mkdir(tmpDir, { recursive: true });

    try {
      // 1. Source as file
      const srcPath = path.join(tmpDir, "source.md");
      await fs.writeFile(srcPath, payload.source_text);

      // 2. Create notebook
      const title = payload.title_hint ?? `humanish-deck-${requestId.slice(0, 8)}`;
      const { stdout: nb } = await exec("notebooklm", ["notebook", "create", title, "--json"], { env: cliEnv });
      const notebookId = JSON.parse(nb).notebook.id;

      // 3. Add + wait for source
      const { stdout: src } = await exec("notebooklm", ["source", "add", srcPath, "--json"], { env: cliEnv });
      const sourceId = JSON.parse(src).source.id;
      await exec("notebooklm", ["source", "wait", sourceId], { env: cliEnv });

      // 4. Generate slide deck
      const { stdout: gen } = await exec("notebooklm", ["generate", "slide-deck", "-s", sourceId, "--json"], { env: cliEnv, timeout: 60_000 });
      const taskId = JSON.parse(gen).task_id;

      // 5. Wait for artifact (~8 min typical)
      await exec("notebooklm", ["artifact", "wait", taskId], { env: cliEnv, timeout: 20 * 60_000 });

      // 6. Download PDF
      const pdfPath = path.join(tmpDir, "deck.pdf");
      await exec("notebooklm", ["download", "slide-deck", pdfPath, "-a", taskId, "--format", "pdf"], { env: cliEnv });
      const pdfStat = await fs.stat(pdfPath);

      // 7. Upload to wooow.now (UPLOAD_TOKEN tier — no quota)
      const fd = new FormData();
      fd.append("file", new Blob([await fs.readFile(pdfPath)], { type: "application/pdf" }), "deck.pdf");
      if (payload.title_hint) fd.append("title", payload.title_hint);
      const wooow = await fetch("https://api.wooow.now/api/decks", {
        method: "POST",
        headers: { authorization: `Bearer ${env.WOOOW_UPLOAD_TOKEN}` },
        body: fd,
      });
      if (!wooow.ok) throw new Error(`wooow_upload_failed:${wooow.status}`);
      const { id: wooowId } = await wooow.json() as { id: string };

      return {
        wooow_url: `https://wooow.now/${wooowId}`,
        title,
        bytes: pdfStat.size,
        notebooklm_artifact_id: taskId,
      };
    } finally {
      await fs.rm(tmpDir, { recursive: true, force: true });
    }
  },
};
```

**4.2 Profile freshness after each run.** Immediately after a successful action run (any action), the runner refreshes the profile's `storage_state`. NotebookLM-py's per-call `RotateCookies` mechanic advances `__Secure-1PSIDTS`. To capture the rotation:
- After the action's main work succeeds, run `notebooklm` once more with `NOTEBOOKLM_AUTH_JSON=<original>` and capture the *updated* JSON output of `notebooklm auth check --json` (which writes the rotated state to a fresh storage_state field, per `SKILL.md`).
- Re-encrypt with AAD = profile name. Atomic rename `<profile>.bin.tmp` → `<profile>.bin`.
- Skip refresh on action failure (don't persist a state that may be partially corrupted).

**4.3 Cookie keepalive cron.** A timer inside the action-runner Node process runs every 5 minutes:
- For each profile under `/data/profiles/` whose name starts with `google-`:
  - Skip if `in_flight[<profile>]` is set (an active `/run` is using this profile).
  - Decrypt → `notebooklm list --json` with `NOTEBOOKLM_AUTH_JSON=<state>` → capture refreshed state → re-encrypt → atomic rename.
- Don't log success cases (would flood the audit log). Log failures (cookie genuinely expired) — surface via `/api/profiles` returning `{name, status: "expired"}`.

## Phase 7 — Hardening (before any external user touches it)

### What to implement

- **Action allowlist.** Hardcoded `ACTION_ALLOWLIST: Set<string> = new Set(["notebooklm.generate-deck"])` in `packages/broker/src/actions.ts` and `packages/box/action-runner/src/actions/index.ts`. `POST /api/mint` rejects unknown action_ids with 400 `action_not_allowed`. CI step greps for hardcoded usage: `git grep -nE 'ACTION_ALLOWLIST' packages/` must show at least one explicit gate per service.
- **Audit log retention.** Rotate `/data/audit.log` daily (logrotate or a tiny cron in the runner). Keep 30 days on the box; older entries auto-deleted. Each line is fixed-format and contains: `<iso>\t<request_id>\t<profile>\t<action_id>\t<status>\t<bytes_returned>`. No payload. No PII beyond profile name.
- **Rate limiting.** Per-bearer (in KV): 1 RPS, 3 calls/min, 10 calls/hour. Most bearers are max_calls=1 anyway, so this is paranoid defense. Per-session-cookie on `/api/mint`: 30 mints/hour.
- **Cookie expiry UX.** When the runner returns `auth_expired` (notebooklm-py 401), the broker exposes it on `GET /api/profiles` as `{name, status: "expired", expired_at}`. Dashboard renders a yellow banner: "Your `google-personal` profile expired — reauth here." One click → reauth flow from Phase 3.
- **Residential proxy support.** Skip in MVP. Document in README as the first place to add it if Google starts flagging datacenter-IP login attempts.
- **Backup of profile blobs.** Skip in MVP. Loss of profile blobs = "log in again, one time." Document as acceptable.
